# 이 책에 대하여

> **취약점 분석 바이블**은 입문자가 처음부터 따라오고, 시니어가 옆에 두고 찾아보는 **살아있는 레퍼런스**입니다.
> 종이책처럼 한 번 쓰고 끝나지 않습니다. 새 CVE가 나오면 사례가 추가되고, 도구가 바뀌면 장이 개정됩니다.

## 이 책이 다른 점

| 보통의 보안 책 | 이 책 |
|---|---|
| 저자의 지식을 한 번에 담는다 | 커뮤니티가 계속 갱신한다 |
| 가상의 예제 코드 | **실제 CVE와 실제 패치 diff** |
| "환경은 알아서 구축하세요" | `docker compose up` 한 줄로 실습 환경 |
| 장마다 구성이 다르다 | **모든 장이 같은 템플릿**. 어디를 펴도 같은 방식으로 읽힌다 |
| 독자 수준이 하나 | 🟢 입문 · 🟡 실무 · 🔴 시니어 배지로 레벨 표시 |

## 구성

```
1부 기초        취약점이 무엇이고, 어떻게 분류하고, 어디까지 허용되는가
2부 방법론      정보 수집 → 위협 모델링 → 정적 → 동적 → 검증 → 보고
3부 웹          인젝션, 인증, 접근 제어, 역직렬화 ...
4부 바이너리    메모리, 오버플로, 힙, UAF, 완화 기법, ROP, 퍼징
5부 확장        모바일, 클라우드, IoT, 공급망, AI/LLM
6부 도구        언제 무엇을 쓰는가
7부 워크스루    실제 CVE를 처음부터 끝까지
8부 보고        보고서, 영향도, 패치 검증
부록            치트시트, 용어집, 참고 자료, 기여 가이드
```

3부와 4부가 이 책의 중심축입니다. 5부는 그 지식이 다른 영역에서 어떻게 변형되는지를 다룹니다.

## 모든 취약점 장의 구조

3부와 4부의 모든 장은 다음 10개 섹션을 **같은 순서**로 갖습니다.

1. 원리
2. 발생하는 코드 패턴
3. 탐지 방법 (정적 / 동적)
4. 실습 🧪
5. 익스플로잇 검증
6. 방어
7. 우회 기법 🔴
8. 실제 CVE 사례
9. 체크리스트
10. 더 읽기

입문자는 1~4와 6, 9를 읽고, 실무자는 전체를, 시니어는 7과 8을 중심으로 봅니다. [SQL 인젝션](part3-web/01-sql-injection.md) 장이 이 구조의 기준(모범 장)입니다.

## 상태 표시

모든 장 상단에 상태가 있습니다.

| 배지 | 의미 |
|---|---|
| 📝 초안 | 뼈대와 핵심 내용만 있음. 보강 기여 환영 |
| 🔄 개정중 | 내용은 있으나 최신화 또는 검수 진행 중 |
| ✅ 검수완료 | 2명 이상이 검수함. 연 1회 재검수 |

지금 이 책의 대부분은 📝 초안입니다. 그것이 "살아있는 책"의 출발점입니다. 페이지 우상단의 ✏️ 아이콘을 누르면 바로 고칠 수 있습니다.

## ⚠️ 윤리 고지

이 책의 모든 기법은 **본인이 소유하거나 명시적으로 허가받은 시스템**에서만 사용해야 합니다. 실습 환경(`labs/`)은 격리된 로컬 네트워크에서만 실행하세요. 자세한 내용은 [1부 4장 윤리와 법적 범위](part1-foundations/04-ethics-and-law.md)를 보세요.
