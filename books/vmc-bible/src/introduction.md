# 이 책에 대하여

> **취약점관리센터 바이블**은 한국인터넷진흥원(KISA) 디지털위협대응본부 **취약점관리센터**에서 일하는 사람을 위한 한 권입니다.
> 센터가 조직으로서 어떻게 움직이는지(제1편), 분석가가 손으로 무엇을 하는지(제2편), 그 둘이 실제 업무에서 어떻게 만나는지(제3편)를 한 책에 담았습니다.
> 처음 온 사람은 "여기가 무슨 일을 하는 곳인가"를, 오래 있던 사람은 "무엇이 바뀌었나"를, 다른 부서에서 온 사람은 "내가 하던 일과 어떻게 이어지나"를 찾을 수 있게 썼습니다.

## 세 편

```
제1편 센터와 제도    왜 생겼고, 어디에 있고, 무엇을 하는가. 신고포상제, 상시 신고조치제, 포털, AI, 협업, 법
제2편 분석 기술      취약점의 원리, 방법론, 웹·바이너리·확장 영역, 도구, 실제 CVE 워크스루, 보고서
제3편 현장 적용      센터 업무 네 단계(입수·분석 → 검증 → 조치 → 공지)에서 제2편의 기술을 쓰는 법. 온보딩
부록                용어집, 치트시트, 연표, FAQ, 출처, 내부 확인 목록, 기여, 참고 자료
```

제1편은 공개 자료로 쓴 조직·제도 이야기이고, 제2편은 실제 CVE와 Docker 실습으로 배우는 기술서이며, 제3편은 둘을 잇는 다리입니다. 바쁘면 [독자별 읽기 경로](reading-paths.md)에서 자기 경로만 따라가면 됩니다.

## ⚠️ 먼저 읽어 주세요

**제1편과 제3편의 센터 관련 서술**은 공개된 자료(KISA 보도자료와 누리집, 정부 발표, 언론 보도, 국정감사 자료)만으로 쓴 **비공식 초안**입니다.

- KISA의 공식 문서가 아닙니다. 내부 규정, 업무 매뉴얼, 조직도와 다르면 **내부 자료가 우선**입니다.
- 공개 자료로 확인할 수 없는 곳에는 🔎 **내부 확인** 표시를 달았습니다. [부록 F](appendix/f-verify.md)에 목록이 있습니다.
- 숫자와 날짜에는 📎 **출처**를 달았습니다. [부록 E](appendix/e-sources.md)에 전체 목록이 있습니다.

**제2편의 모든 기법**은 본인이 소유하거나 명시적으로 허가받은 시스템에서만 사용해야 합니다. 실습 환경은 격리된 로컬에서만 실행하세요. [제2편 기초 4장](vol2-tech/part1-foundations/04-ethics-and-law.md)

## 이 책의 원칙

1. **모든 장은 같은 템플릿**을 따른다. 어디를 펴도 같은 방식으로 읽힌다.
2. **사례는 실제**만 쓴다. 기술은 실제 CVE와 패치 diff, 조직은 출처 있는 공개 자료.
3. **실습은 코드로 제공**한다. `docker compose up` 한 줄.
4. **레벨을 표시**한다. 🟢 입문 · 🟡 실무 · 🔴 시니어
5. **계속 개정**한다. 상태 배지(📝 초안 · 🔄 개정중 · ✅ 검수완료)와 변경 이력을 장마다.
6. **모르는 것은 모른다고 쓴다.** 🔎
