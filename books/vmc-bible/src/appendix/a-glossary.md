## 기술 용어

| 용어 | 뜻 | 장 |
|---|---|---|
| **가젯** (gadget) | `ret` 같은 분기 명령으로 끝나는 짧은 기존 코드 조각. ROP에서는 이를 이어 붙여 원하는 동작을 만들고, 역직렬화에서는 기존 클래스의 메서드가 가젯이 된다 | [ROP](../vol2-tech/part4-binary/08-rop.md) |
| **가젯 체인** (gadget chain) | 역직렬화 시 기존 클래스의 메서드를 연쇄 호출해 임의 코드 실행에 이르는 경로 | [역직렬화](../vol2-tech/part3-web/07-deserialization.md) |
| **경쟁 조건** (race condition) | 둘 이상의 동작이 겹쳐 실행될 때 순서·타이밍에 따라 결과가 달라져 생기는 취약점. 확인과 사용 사이에 상태가 바뀌는 TOCTOU가 대표적 | [경쟁 조건](../vol2-tech/part3-web/10-race-condition.md) |
| **공격 표면** (attack surface) | 외부 입력이 들어오는 모든 지점 | [공격 표면](../vol2-tech/part1-foundations/03-attack-surface.md) |
| **블라인드 인젝션** (blind injection) | 결과가 직접 보이지 않고 참/거짓이나 시간 차이로만 알 수 있는 인젝션 | [SQL 인젝션](../vol2-tech/part3-web/01-sql-injection.md) |
| **소스·싱크·새니타이저** (source · sink · sanitizer) | 정적 분석의 데이터 흐름 모델. 소스는 외부 입력이 들어오는 지점, 싱크는 그 값이 위험한 동작(쿼리 실행, 명령 실행, 메모리 복사)에 쓰이는 지점, 새니타이저는 그 사이에서 값을 검증·정화해 흐름을 끊는 지점이다. 소스에서 싱크까지 새니타이저 없이 닿는 경로가 취약점 후보다 | 제2편 [방법론 4장](../vol2-tech/part2-methodology/04-static-analysis.md) |
| **신뢰 경계** (trust boundary) | 신뢰 수준이 달라지는 지점. 취약점은 거의 항상 여기서 생긴다 | [취약점이란](../vol2-tech/part1-foundations/01-what-is-vulnerability.md) |
| **역직렬화** (deserialization) | 직렬화된 데이터를 객체로 되돌리는 것. 입력을 신뢰하면 코드 실행 | [역직렬화](../vol2-tech/part3-web/07-deserialization.md) |
| **완화 기법** (mitigation) | ASLR, NX, Canary, PIE, RELRO, CFI 등 익스플로잇을 어렵게 하는 장치 | [완화 기법](../vol2-tech/part4-binary/07-mitigations.md) |
| **익스플로잇** (exploit) | 취약점을 실제로 이용하는 코드나 절차 | [취약점이란](../vol2-tech/part1-foundations/01-what-is-vulnerability.md) |
| **파라미터화된 쿼리** (parameterized query) | 쿼리와 입력을 분리해 전달하는 방식. SQL 인젝션의 근본 방어 | [SQL 인젝션](../vol2-tech/part3-web/01-sql-injection.md) |
| **퍼징** (fuzzing) | 예상 밖 입력을 자동으로 대량 주입해 결함을 찾는 기법 | [퍼징](../vol2-tech/part4-binary/09-fuzzing.md) |
| **ADP** | Authorized Data Publisher. CVE 레코드에서 CNA 컨테이너 외에 CVSS·CWE·SSVC 같은 보강 정보를 자기 컨테이너에 덧붙일 권한이 있는 조직. CISA의 Vulnrichment가 대표 사례 | [CWE · CVE · CVSS](../vol2-tech/part1-foundations/02-cwe-cve-cvss.md) |
| **ASLR** | Address Space Layout Randomization. 메모리 주소 무작위화 | [완화 기법](../vol2-tech/part4-binary/07-mitigations.md) |
| **CSRF** | Cross-Site Request Forgery. 로그인된 사용자의 브라우저가 공격자가 꾸민 요청을 사용자 의도 없이 대상 사이트에 보내게 하는 공격. 브라우저가 쿠키를 자동으로 붙이는 성질을 이용하며, SameSite 쿠키와 토큰으로 막는다 | [인증과 세션](../vol2-tech/part3-web/04-auth-session.md) |
| **CVSS 벡터** (벡터 문자열, vector string) | CVSS 점수의 근거가 되는 지표 값을 한 줄로 적은 문자열. 예: `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`(공격 경로 네트워크, 복잡도 낮음, 권한·사용자 상호작용 불필요, 기밀성·무결성·가용성 모두 높음 → 9.8). 점수만 적지 말고 벡터를 함께 적어야 다른 사람이 판단을 검증할 수 있다 | 제2편 [기초 2장](../vol2-tech/part1-foundations/02-cwe-cve-cvss.md), [보고 2장](../vol2-tech/part8-reporting/02-severity.md) |
| **DoS** | Denial of Service, 서비스 거부. 자원 고갈이나 크래시로 정상 사용자가 서비스를 쓸 수 없게 만드는 공격. 여러 출발지에서 동시에 하면 DDoS | [취약점이란](../vol2-tech/part1-foundations/01-what-is-vulnerability.md) |
| **FORTIFY_SOURCE** | GCC·glibc의 컴파일 시 보강 옵션. 버퍼 크기를 컴파일 시점에 알 수 있는 `memcpy`·`strcpy`·`sprintf` 등 호출을 길이 검사 버전(`__memcpy_chk` 등)으로 바꿔, 실행 중 오버플로를 잡아 중단시킨다 | [완화 기법](../vol2-tech/part4-binary/07-mitigations.md) |
| **GOT** | Global Offset Table. 동적 링크된 바이너리에서 외부 함수·변수의 실제 주소를 담는 표. 쓰기 가능하면 덮어쓰기 표적이 되고, Full RELRO가 이를 읽기 전용으로 만든다 | [완화 기법](../vol2-tech/part4-binary/07-mitigations.md), [ROP](../vol2-tech/part4-binary/08-rop.md) |
| **IDOR** | Insecure Direct Object Reference. ID만 바꿔 남의 자원에 접근 | [접근 제어](../vol2-tech/part3-web/05-access-control.md) |
| **IMDS** | Instance Metadata Service. 클라우드 VM이 자기 메타데이터와 임시 자격증명을 받는 링크 로컬 주소(169.254.169.254)의 서비스. SSRF의 대표 표적이며, IMDSv2는 먼저 PUT 요청으로 세션 토큰을 받아 이후 요청의 헤더에 넣게 하므로 PUT이나 임의 헤더를 보낼 수 없는 단순 SSRF를 막는다 | [SSRF](../vol2-tech/part3-web/03-ssrf.md), [클라우드](../vol2-tech/part5-extended/02-cloud.md) |
| **mXSS** | Mutation XSS. 브라우저가 HTML을 파싱하고 다시 직렬화하는 과정에서 마크업이 바뀌어, 정화기(sanitizer)를 통과한 입력이 DOM에 들어간 뒤 스크립트로 변하는 XSS | [XSS](../vol2-tech/part3-web/02-xss.md) |
| **N-day** | 패치가 나왔지만 적용되지 않은 취약점 | [취약점이란](../vol2-tech/part1-foundations/01-what-is-vulnerability.md) |
| **PLT** | Procedure Linkage Table. 외부 함수 호출을 GOT 항목에 적힌 주소로 넘기는(`jmp *GOT[n]`) 작은 스텁 코드의 묶음. ret2plt는 반환 주소를 이 스텁으로 돌려, 라이브러리의 실제 주소를 모른 채 그 함수를 호출한다 | [ROP](../vol2-tech/part4-binary/08-rop.md) |
| **PoC** | Proof of Concept. 취약점이 실제임을 보이는 최소 증명. 센터 업무의 "재현"은 PoC가 자기 환경에서 돌아가는지 확인하는 일 | [익스플로잇 검증](../vol2-tech/part2-methodology/06-exploit-verification.md) |
| **RCE** | Remote Code Execution, 원격 코드 실행. 공격자가 네트워크 너머에서 대상 시스템에 임의 코드를 실행시키는 결과. 결과를 가리키는 말이라 CWE가 아니며, 원인(역직렬화, 명령 인젝션, 버퍼 오버플로 등)을 따로 적는다 | [CWE · CVE · CVSS](../vol2-tech/part1-foundations/02-cwe-cve-cvss.md) |
| **ROP** | Return-Oriented Programming. 기존 코드 조각을 이어 붙여 실행 | [ROP](../vol2-tech/part4-binary/08-rop.md) |
| **safe-linking** | glibc 2.32부터 tcache·fastbin의 단일 연결 리스트 포인터를 저장 위치 주소(`>> 12`)와 XOR해 보호하는 기법. 힙 주소를 누출하지 않으면 포인터 위조가 어려워진다 | [힙 취약점](../vol2-tech/part4-binary/04-heap.md) |
| **SAST** | Static Application Security Testing. 정적 분석 (Semgrep, CodeQL) | [정적 분석기](../vol2-tech/part6-tools/05-sast-semgrep-codeql.md) |
| **SBOM** | Software Bill of Materials. 소프트웨어를 구성하는 컴포넌트·버전·의존성의 목록. SPDX·CycloneDX 형식이 표준이며 공급망 취약점 영향 범위를 찾는 출발점 | [공급망](../vol2-tech/part5-extended/04-supply-chain.md) |
| **SCA** | Software Composition Analysis. 의존성 목록을 알려진 취약점 DB와 대조해 취약한 컴포넌트를 찾는 분석. SAST가 자기 코드를 보는 것이라면 SCA는 가져다 쓴 코드를 본다 | [정보 수집](../vol2-tech/part2-methodology/02-recon.md), [공급망](../vol2-tech/part5-extended/04-supply-chain.md) |
| **SSRF** | Server-Side Request Forgery. 서버가 공격자 지정 URL로 요청 | [SSRF](../vol2-tech/part3-web/03-ssrf.md) |
| **SSTI** | Server-Side Template Injection. 사용자 입력이 템플릿 데이터가 아니라 템플릿 문자열 자체로 들어가, 템플릿 엔진이 그것을 평가하면서 코드 실행에 이르는 취약점 | [SSTI](../vol2-tech/part3-web/09-ssti.md) |
| **SSVC** | Stakeholder-Specific Vulnerability Categorization. 점수 대신 의사결정 트리로 대응 수준을 정하는 CERT/CC·CISA의 체계. 결정 포인트(악용 여부 Exploitation, 자동화 가능성 Automatable, 기술적 영향 Technical Impact, 임무·안전 영향)를 거쳐 Track · Track\* · Attend · Act 넷 중 하나로 끝난다. CISA ADP는 앞의 세 결정 포인트 값을 CVE 레코드에 넣는다 | [CWE · CVE · CVSS](../vol2-tech/part1-foundations/02-cwe-cve-cvss.md) |
| **tcache** | thread-local cache. glibc 2.26부터 `malloc`이 스레드별로 작은 청크를 크기별 단일 연결 리스트로 모아 두는 캐시. 검사가 느슨해 힙 익스플로잇의 첫 표적 | [힙 취약점](../vol2-tech/part4-binary/04-heap.md) |
| **UAF** | Use-After-Free. 해제된 메모리를 계속 사용 | [UAF](../vol2-tech/part4-binary/05-uaf.md) |
| **WAF** | Web Application Firewall. HTTP 요청·응답을 규칙으로 검사해 공격 패턴을 차단하는 장치. 우회가 가능하므로 패치까지 시간을 버는 임시 완화책이지 근본 수정이 아니다 | [SQL 인젝션](../vol2-tech/part3-web/01-sql-injection.md), [제3편 1부 3장](../vol3-practice/01-workflow-tech/03-remediation.md) |
| **XSS** | Cross-Site Scripting. 입력이 브라우저에서 스크립트로 실행 | [XSS](../vol2-tech/part3-web/02-xss.md) |
| **XXE** | XML External Entity. XML 파서가 외부 개체(entity) 선언을 해석하게 두어 로컬 파일 읽기·SSRF·DoS에 이르는 취약점 | [XXE](../vol2-tech/part3-web/08-xxe.md) |
| **0-day** | 벤더가 모르거나 패치가 없는 취약점 | [취약점이란](../vol2-tech/part1-foundations/01-what-is-vulnerability.md) |
