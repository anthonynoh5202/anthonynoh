# 전입 직원: 다른 팀·본부에서 오신 분께

| 레벨 | 상태 | 최종 개정 |
|---|---|---|
| 🟢 | 🔄 개정중 | 2026-10-22 |

> **한눈에 보기**
> 전입 직원은 신입과 다르다. KISA를 알고, 사람을 알고, 자기 분야를 안다.
> 모르는 것은 **취약점관리라는 시간축과 상대**다. 이 장은 출신 부서별로 "이미 아는 것"과 "새로 알아야 할 것"을 나눈다.

## 공통: 전입자가 먼저 할 것

- [ ] [제1편 1부 4장 업무 흐름](../../vol1-center/01-understanding/04-workflow.md), 특히 3절 "시간축" 을 읽는다
- [ ] [제1편 3부 10장 원내 협업](../../vol1-center/03-partners/10-internal.md)에서 **자기 이전 부서와 센터의 접점**을 찾는다. 없으면 그린다. 그것이 당신의 첫 기여다
- [ ] [13장 신입 체크리스트](13-new-hire.md)에서 "30일" 항목만 2주 안에 끝낸다. 60일·90일은 신입과 같다
- [ ] 이전 부서에서 센터에 "늘 아쉬웠던 것"을 메모해 둔다. 센터 안에서 그것을 고칠 수 있는 자리에 왔다

## 침해대응(KrCERT/CC)에서 오셨다면

| 이미 아는 것 | 새로 알아야 할 것 |
|---|---|
| 사고 분석, IoC, 공격 기법 | 사고가 **나기 전**의 일. 성과가 "막은 사고"라서 보이지 않는다 |
| 시간 단위의 긴박함 | 일~주 단위의 제조사 조율. 기다리는 법, 그리고 악용 중 건은 예외라는 것 |
| 피해 기관 응대 | **제조사**와 **신고자** 응대. 제조사는 고칠 의무가 모호하고, 신고자는 포상과 공개를 기다린다 |
| 취약점이 어떻게 악용되는가 | 취약점이 **어떻게 평가되고 공개되는가**. CVSS, 파급도, 공개 제한, CVE 발급 |

당신의 강점: 분석가들이 "이론상 Critical"이라 할 때 "실제로 이렇게 쓰인다"를 말할 수 있다. 파급도 판정에 그 감각을 넣어 달라.

## 정책·법무·제도 부서에서 오셨다면

| 이미 아는 것 | 새로 알아야 할 것 |
|---|---|
| 법령, 규정, 정부 협의 | 취약점 하나의 **기술적 실체**. 재현이 안 되면 제도도 안 돌아간다 |
| 국정감사, 예산, 보고 | 분석가의 일이 왜 시간이 걸리는지. "10건 중 5~6건" 검증의 무게 |
| 유관기관 관계 | **제조사**라는 새 상대. 공공기관처럼 움직이지 않는다 |

당신의 강점: 2027년 제도화([제1편 3부 12장](../../vol1-center/03-partners/12-legal.md))는 당신의 영역이다. 시범사업 데이터를 논거로 바꾸는 일을 맡아 달라. 제2편 [기초 1장](../../vol2-tech/part1-foundations/01-what-is-vulnerability.md)과 [2장](../../vol2-tech/part1-foundations/02-cwe-cve-cvss.md)만 읽어도 분석가와 대화가 된다.

## 인증·평가·점검 부서에서 오셨다면

| 이미 아는 것 | 새로 알아야 할 것 |
|---|---|
| 점검 방법론, 체크리스트, 보고서 | **신규** 취약점. 체크리스트에 없는 것을 찾고 판단하는 일 |
| 기준 대비 적합/부적합 | 위험도의 **상대 평가**. 같은 취약점이 기관마다 다른 우선순위 |
| 피평가 기관 응대 | 조치가 **강제되지 않는** 상대. 설득의 기술 ([제1편 2부 8장](../../vol1-center/02-programs/08-assessment-support.md)) |

당신의 강점: 보고서 품질과 재현 절차의 엄밀함. "권고에 그친다"는 지적([제1편 2부 8장 2절](../../vol1-center/02-programs/08-assessment-support.md))에 대한 답은 당신이 쓰던 추적 방식에 있다.

## 산업지원·AI보안 부서에서 오셨다면

| 이미 아는 것 | 새로 알아야 할 것 |
|---|---|
| 기업 생태계, 보안 산업, 기술 과제 | 취약점의 **민감성**. 공개 전 정보는 기업 지원 논리로 흘러서는 안 된다 |
| AI 기술, 모델 | AI 결과의 **재검증** 문화. 모델 성능이 아니라 유효율과 기각 사유가 지표 |
| 기업과의 협력 관계 | 같은 기업이 **제조사**로서 조치 요청을 받는 입장이 된다. 역할 전환을 명확히 |

당신의 강점: 한국형 보안 AI([제1편 2부 9장 3절](../../vol1-center/02-programs/09-ai.md))와 센터 현장을 잇는 사람. 분석가가 무엇을 필요로 하는지 기술 과제로 번역해 달라.

## 지역정보보호지원센터에서 오셨다면

| 이미 아는 것 | 새로 알아야 할 것 |
|---|---|
| 중소기업의 현실, 보안 담당자 부재 | 전국 단위의 **파급도** 판단. 한 기업이 아니라 한 제품군 |
| 현장 점검, 기술지원 | 제조사 조율과 **공개** 결정 |

당신의 강점: 센터의 공지와 기술지원이 중소기업에 실제로 닿는지 아는 사람. [제1편 2부 8장 4절](../../vol1-center/02-programs/08-assessment-support.md)을 당신이 다시 써 달라.
