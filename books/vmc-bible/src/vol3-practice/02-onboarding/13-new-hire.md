## 첫 주

첫 주는 읽고, 둘러보고, 신청하는 주다. 구축은 하지 않는다. 항목을 셋으로 나눈 것은 되는 조건이 다르기 때문이다. 책 안에서 끝나는 것, 인터넷 접속이 필요한 것, 센터 안에서만 되는 것(🔎).

**이 책 안에서 끝나는 것**

- [ ] [제1편 1부 센터 이해하기](../../vol1-center/01-understanding/01-why.md) 네 장을 읽는다
- [ ] [제2편 기초 6장 분석 환경 구축](../../vol2-tech/part1-foundations/06-analysis-workstation.md)을 **읽는다**. 자원 신청은 아래 🔎 항목, 구축 자체는 30일 항목이다
- [ ] [부록 A 용어집](../../appendix/a-glossary.md)을 한 번 훑는다

**외부 사이트가 필요한 것** (인터넷 접속)

- [ ] 센터장 인터뷰 기사 하나를 읽는다 ([부록 E](../../appendix/e-sources.md))
- [ ] 포털(knvd.krcert.or.kr)과 보호나라(boho.or.kr)를 열어 메뉴를 전부 눌러 본다
- [ ] 보호나라 보안공지 최근 5건을 읽고 [제1편 2부 7장 4절](../../vol1-center/02-programs/07-portal-advisory.md) 과제를 한 건 한다

**센터 안에서만 되는 것** 🔎

- [ ] 센터 구성원과 각자의 담당을 한 장에 그린다 🔎
- [ ] 접근 권한, 시스템 계정, 메일 그룹을 받는다 🔎
- [ ] 분석용 하드웨어·VM 자원 신청 절차와 담당을 확인하고 신청한다 🔎

## 30일: 흐름 이해

- [ ] [제1편 2부 제도와 서비스](../../vol1-center/02-programs/00-index.md) 다섯 장을 읽는다
- [ ] [제2편 기초 6장](../../vol2-tech/part1-foundations/06-analysis-workstation.md)을 따라 분석 VM을 만들고 `setup-analyst.sh --check`를 통과시킨다. 첫 주에 신청한 자원이 나와야 한다
- [ ] 입수 경로 네 가지(내부, 신고포상제, 118, 유관기관)에서 각각 실제 건 하나씩을 선배와 함께 본다 🔎
- [ ] 분석 단계의 산출물(분석 보고 양식)을 읽고, 과거 건 하나를 양식에 맞춰 다시 써 본다 🔎
- [ ] 제조사에 보낸 조치 요청 메일 샘플을 읽는다 🔎
- [ ] AI 1차 분석 결과와 분석가 재검증 결과를 나란히 비교해 본다 ([제1편 2부 9장](../../vol1-center/02-programs/09-ai.md))
- [ ] 제2편 [기초](../../vol2-tech/part1-foundations/01-what-is-vulnerability.md)와 [방법론 1장](../../vol2-tech/part2-methodology/01-overview.md)을 읽는다
- [ ] 제2편 [웹 1장 SQL 인젝션](../../vol2-tech/part3-web/01-sql-injection.md) 실습을 끝까지 한다. 센터 업무는 "재현"이 핵심이고, 재현은 손으로 배운다
- [ ] 멘토와 30일 회고: 흐름 네 단계를 설명해 보인다

## 60일: 한 단계 직접

- [ ] 선배 감독 아래 **분석 단계** 한 건을 맡는다: 신규 여부 판단, 파급도 판정, 재현
- [ ] 재현 결과를 제2편 [보고 1장 보고서 구조](../../vol2-tech/part8-reporting/01-report-structure.md)에 맞춰 쓴다
- [ ] 제조사 또는 기관에 보내는 조치 요청 초안을 쓴다. 선배가 고친 부분을 기록한다
- [ ] [제1편 3부 함께 일하는 곳](../../vol1-center/03-partners/00-index.md)을 읽고, 자기 업무에서 만날 유관기관 두 곳의 창구를 확인한다 🔎
- [ ] 신고자 응대 하나를 선배와 함께 한다. "지금 어느 단계인가", "언제 공개 가능한가"에 답해 본다
- [ ] 제2편에서 자기 담당 분야의 장 두 개를 더 읽는다
- [ ] 멘토와 60일 회고: 분석 한 건의 판단 근거를 설명해 보인다

## 90일: 한 건 끝까지

- [ ] 입수부터 공지(또는 종결)까지 **한 건을 주담당**으로 맡는다
- [ ] 그 건의 기록을 [제1편 1부 4장 4절](../../vol1-center/01-understanding/04-workflow.md) 사례 틀로 정리해 센터에 공유한다
- [ ] 이 책에서 틀렸거나 비어 있던 것 하나 이상을 고친다 (✏️ 아이콘)
- [ ] 자기 역할을 [제1편 1부 3장 이해관계자 지도](../../vol1-center/01-understanding/03-roles.md) 위에 표시한다
- [ ] 멘토와 90일 회고: 다음 90일의 목표를 정한다

## 흔한 어려움

| 어려움 | 조언 |
|---|---|
| 기술이 부족하다고 느낀다 | 센터 업무의 절반은 기술이 아니라 **판단과 소통**이다. 재현은 배우면 되고, 제2편이 그 교재다 |
| 모든 제보를 다 중요하게 느낀다 | "국내에서, 지금, 실제로"를 매번 묻는다. 우선순위가 센터의 핵심 역량이다 |
| 제조사가 답을 안 한다 | 혼자 기다리지 않는다. 선배에게 에스컬레이션 기준을 묻는다 🔎 |
| 신고자가 화를 낸다 | 단계와 일정을 정확히 알려 주는 것만으로 대부분 풀린다. 약속할 수 없는 것은 약속하지 않는다 |
| 인력이 부족해 보인다 | 사실이다 ([제1편 1부 2장 3절](../../vol1-center/01-understanding/02-where.md)). 그래서 기록과 자동화가 중요하다. 자기 일을 다음 사람이 이어받을 수 있게 남긴다 |
