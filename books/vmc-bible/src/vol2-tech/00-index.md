# 제2편 읽는 법

제2편은 **분석가가 손을 움직이는 방법**을 다루는 기술서다. 센터 밖의 독자도 이 편만 따로 읽을 수 있다.

## 구성

```
기초          취약점이 무엇이고, 어떻게 분류하고, 어디까지 허용되는가
방법론        정보 수집 → 위협 모델링 → 정적 → 동적 → 검증 → 보고
웹            인젝션, 인증, 접근 제어, 역직렬화 ...
바이너리      메모리, 오버플로, 힙, UAF, 완화 기법, ROP, 퍼징
확장          모바일, 클라우드, IoT, 공급망, AI/LLM
도구          언제 무엇을 쓰는가
워크스루      실제 CVE를 처음부터 끝까지
보고          보고서, 영향도, 패치 검증
```

웹과 바이너리가 중심축이다. 확장은 그 지식이 다른 영역에서 어떻게 변형되는지를 다룬다.

## 모든 취약점 장의 구조

웹과 바이너리의 모든 장은 다음 10개 섹션을 **같은 순서**로 갖는다.

1. 원리
2. 발생하는 코드 패턴
3. 탐지 방법 (정적 / 동적)
4. 실습 🧪
5. 익스플로잇 검증
6. 방어
7. 우회 기법 🔴
8. 실제 CVE 사례
9. 체크리스트
10. 더 읽기

입문자는 1~4와 6, 9를 읽고, 실무자는 전체를, 시니어는 7과 8을 중심으로 본다. [SQL 인젝션](part3-web/01-sql-injection.md) 장이 이 구조의 기준(모범 장)이다.

## 레벨별 경로

### 🟢 보안을 처음 접한다면
1. [기초](part1-foundations/01-what-is-vulnerability.md)를 순서대로. 특히 [실습 환경 구축](part1-foundations/05-lab-setup.md)은 반드시 따라 한다.
2. [방법론 개요](part2-methodology/01-overview.md)로 큰 그림.
3. [SQL 인젝션](part3-web/01-sql-injection.md)을 실습까지 끝낸다.
4. 웹의 🟢 장들을 골라 읽는다. 각 장에서 1~4, 6, 9 섹션만 읽어도 된다.
5. 바이너리에 관심이 생기면 [메모리 구조](part4-binary/01-memory-basics.md)부터.

### 🟡 실무 1~3년차라면
- 방법론을 한 번 훑고, 자신의 분석 과정에서 빠진 단계가 있는지 본다.
- "안다고 생각했던" 장의 **7. 우회 기법**과 **8. 실제 CVE 사례**를 읽는다.
- [워크스루](part7-walkthroughs/00-overview.md)를 하나 골라 직접 재현한다.
- [도구](part6-tools/00-when-to-use-what.md)에서 안 써 본 도구 하나를 익힌다.

### 🔴 시니어라면
- 레퍼런스로 쓴다. 검색(`S`)이 가장 빠르다.
- 각 장의 **8. 실제 CVE 사례** 표는 "이 유형의 대표 사례 목록"으로 설계되어 있다.
- 가장 큰 기여는 **7. 우회 기법**과 **워크스루** 작성이다.
